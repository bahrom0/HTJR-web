# Удаление заглушек из пользовательского пути

## Цель

Главная, список документов, редактор и экспорт используют только реальные данные
`api_server`. Папка `new_front` остаётся неизменяемым визуальным референсом.

## Этапы

1. Добавить owner-scoped API списка, карточки и удаления документов.
2. Построить редактор из реальных OCR-строк и crop-изображений.
3. Хранить черновики и подтверждённые исправления на сервере с контролем ревизий.
4. Перевести Home, Documents, Editor и Export с `localStorage` на API.
5. Удалить mock-наборы и неиспользуемые экраны, сохранив legacy redirect-адреса.

## Критерии готовности

- На главной нет выдуманных документов.
- Реальный завершённый OCR открывается в редакторе построчно.
- Выбранная строка показывает реальный crop.
- Правка переживает перезагрузку страницы и подтверждается на сервере.
- Экспорт использует серверный effective text.
- TypeScript, lint, Vite build и backend tests проходят.

## Границы

Не изменять `new_front`, ML-модели и worker-протокол. Тестовые fixtures, loading,
empty и error states не считаются продуктовыми заглушками.
